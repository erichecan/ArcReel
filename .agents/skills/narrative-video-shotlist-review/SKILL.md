# 剧情类短视频分镜脚本审查

审查对象是喂给 AI 视频生成模型的分镜脚本,由若干"视频单元"(unit)组成,每个 unit 通常是几秒钟的一个镜头 + 一句台词,改编自小说、剧本或创作构想。目标不是让描述更华丽,而是让每个 unit **值得单独存在**、写法本身容易被视频生成模型正确渲染,并且**整条脚本拼起来讲的是一个逻辑自洽的故事**。

## 为什么这么审查(先讲透原理,再讲清单)

**多写字不会多花钱,但塞多个动作/反转会让生成更容易失败。** 主流视频生成供应商基本都按"时长 × 分辨率 × 服务档位"计费,和 prompt 字数无关。真正的代价是间接的:一个 3~4 秒的 unit 里塞进两个动作或一次反转,当前的视频生成模型大概率处理不过来——要么表情/动作糊在一起变形,要么只做出其中一个、其余被忽略。效果不满意,用户就要手动点"重新生成",这一次才会真的再计一次费。所以省钱的关键不是少写字,而是让每个 unit 只锁定一个变化,减少要重跑的次数。

**运镜是手段,不是内容。** 一个 unit 之所以让人觉得"就是个运镜,不值得",根源通常是画面主体在这几秒内**没有发生任何情节/情绪变化**——镜头在动,但人物的表情、关系、处境没有任何推进。运镜的作用是引导视线去看一个变化,不能替代变化本身。剧情类脚本里最容易犯这个错的是"环境空镜"和"重复的对视/走路镜头"——好看但不推进故事。

**Prompt 里词的顺序会影响生成质量。** 已验证的外部资料(2026 Director's Cheatsheet,覆盖 Sora 2 / Veo 3.1 / Kling 3 / Runway Gen-4)显示,这些模型对 prompt 中越靠前的词赋权越高,最佳固定顺序是:

```
主体(Subject) → 动作(Action) → 运镜(Camera movement) → 景别/焦段(Lens/framing) → 风格/光线(Style/lighting)
```

顺序打乱(比如把运镜或风格词放最前面)会明显降低生成质量。写 unit 描述时,先说"谁在做什么动作/什么表情变化",运镜和景别放后面修饰,不要开头就是"镜头切向/镜头扫描"。

## 四问检查法(逐个 unit 过一遍)

对脚本里的**每一个** unit 依次问:

1. **画面主体在这几秒内发生了什么情节/情绪变化?** 如果答案是"没有变化,只是镜头在动或人物站在那"(比如纯环境空镜、纯对视、纯走路),这个 unit 是弱的。
2. **这个变化能不能用一句话说清楚(一次动作、一次表情转折、一句关键台词)?** 一次变化配一个 unit,不要在同一个 unit 里塞两次反转或两个情绪转折(比如"震惊→愤怒→落泪"挤在一起,模型大概率只做出其中一个表情)。
3. **这个变化是否需要当前的景别/运镜来配合?** 比如"眼神从躲闪到直视"必须是近景/特写才有意义,全景就浪费了这个表演细节。(参考下方"景别功能对照表"判断依据)
4. **去掉这个 unit,整条脚本是否会缺一个关键情节点、情绪拍点或悬念钩子?** 如果去掉不影响,说明它本该被合并或删除。

任何一个 unit 只要在问题 1 上给出"没有变化"的答案,就判定为**弱单元**,需要改写或合并;其余三问用来判断改写方向和是否该保留独立存在。

## 景别功能对照表

| 景别 | 该表现什么 | 不适合表现什么 |
|---|---|---|
| 远景/全景 | 场景建立、人物之间的空间/权力关系、时间地点转换 | 需要看清的面部表情、微表情变化 |
| 中景/中近景 | 人物之间完整的肢体互动(推搡、拉扯、拥抱、递物) | 需要放大呈现的情绪细节(眼眶泛红、嘴角一抖) |
| 近景/特写 | 面部表情、眼神变化、关键台词的说话瞬间 | 需要多人同框配合的互动(既要看甲的反应又要看乙的动作) |
| 微距/大特写 | 极致细节瞬间(手指颤抖、信物特写、泪珠滑落) | 需要交代动作起止过程的内容,信息量太满时观众会看不清主体是谁 |

判断方法:先确定这个 unit 的核心变化需要观众看清哪个部位/范围,再倒推该用哪个景别,而不是先定景别再往里塞内容。

## 镜头节奏结构

好的剧情类短视频脚本节奏大致是:

`钩子/悬念建立(开场,1~2 个)→ 冲突推进(信息/关系展开,应占多数)→ 情绪高潮/反转(1~2 个)→ 结局或追更钩子(1 个)`

审查时数一下纯建立型 unit(环境空镜、纯氛围、无情节推进)的占比——如果一条 8~9 个 unit 的脚本里有 3 个以上是纯建立/纯氛围,说明情节密度不够,节奏会显得拖沓、抓不住人。

## 整条脚本的检查(逐单元审查之外)

逐个 unit 过完四问之后,再回头把整条脚本当一个整体检查一遍,这些问题在单个 unit 里看不出来:

1. **时长与编号是否对得上**:把所有 unit 的秒数加起来,和用户宣称的总时长比对;检查 unit 编号是否连续(比如 `E1U7` 后面直接跳到 `E1U9`,中间的 `E1U8` 不存在)——编号跳号本身就是证据,不要假设是命名习惯,要向用户确认是否漏传。
2. **情节/情感时间线是否合理**:这一条跟编号是否连续是两回事——编号可能完全连续,但内容顺序颠倒了。按 unit 编号当作播放顺序把情节过一遍(铺垫→冲突→转折→结果),检查有没有"结果排在原因前面"的情况,比如两人已经和好的镜头排在争执还没展开之前,或者反派"黑化"的反应镜头排在触发黑化的事件之前。发现顺序颠倒要点名具体是哪几个 unit 编号冲突,并给出按情节因果应有的正确顺序。
3. **人物状态是否连贯**:同一角色的情绪、所处场景、外观(比如是否已经受伤、衣着是否符合场景)是否跨 unit 保持一致,不能上一个 unit 还在崩溃大哭,下一个 unit 毫无过渡就恢复正常聊天。如果确实需要跳跃,要点出是否缺一个过渡 unit(比如"擦干眼泪、深呼吸"这类衔接镜头)。
4. **结构完整性与悬念收束**:整条脚本是否构成完整的钩子→冲突→高潮→结局(或明确的追更悬念)弧线,开局 3 秒是否有能留住人的钩子、片中埋下的伏笔(比如某句台词、某个道具特写)是否在结尾有呼应或明确留白给下一集,不要埋了没接。
5. **结尾引导(关注/追更/行动号召)前后是否统一**:扫一遍全片台词,看是否同时暗示了两种不同的收尾意图(比如中段台词像是完结感很强的"从此明白了…",结尾又是强烈的"欲知后事下集见")。两种收尾信号同时存在会削弱追更效果,必须收敛成一种。
6. **视觉重复度/留存曲线检查**:统计各 unit 的核心画面主体+景别组合(比如"两人对视中景"算一类),如果同一类组合在全片里出现 3 次以上,即使每个 unit 单独看都通过了四问法,拼起来也会让观众在中段(3~15 秒留存关键窗口)觉得"看过了",完播率下滑。发现这种情况要点名指出重复的 unit 编号,并建议把其中至少一个换成不同的视觉类型(比如从"对视中景"换成"手部特写"或"环境全景")。
7. **静音可读性检查**:短视频平台大量用户是默认静音刷视频的,关键情节信息不能只靠台词的语气/停顿才能读懂,必须脱离声音、只靠画面表情+字幕也能被理解。逐句过一遍台词,标出哪些信息点是纯听觉才能获取的(比如靠哽咽声传达的情绪),提示需要靠画面动作或字幕强调来补足。

## 剧情动作/情绪动词库(参考,不必穷尽)

| 分类 | 动词 | 典型景别 + 运镜 |
|---|---|---|
| 关系互动 | 拉扯、推开、拥抱、对峙、递出、抢过、转身离去 | 中景/中近景 + 固定或轻微跟随,留出两人互动的完整空间 |
| 表情/情绪 | 僵住、颤抖、泛红、咬牙、落泪、强忍、瞪大眼 | 近景/特写 + 固定或缓推,强调表情/眼神的瞬间变化 |
| 悬念/揭示 | 回头、瞥见、翻开、拆开、发现、藏起 | 特写/微距 + 缓推或固定,突出关键信息被看见的瞬间 |
| 场景/关系建立 | 并肩、擦肩、独坐、伫立、远眺 | 全景/远景 + 固定或缓摇,交代人物所处的环境与位置关系 |

## 输出格式

目标产品(ArcReel)里每个 unit 的正文是独立的一个字段(不含 `[unit_id] (Ns)` 这层编号/时长前缀,那是另外两个字段拼出来给人看的),而且目前只能逐个 unit 手动粘贴回填、没有一次性批量导入的入口。所以每个建议修改的 unit 都必须单独给一段"可粘贴文本",内容严格等于改写后要填进那个 unit 正文字段的完整字符串(镜头描述 + `{台词}`),用户复制后不需要再手动删减任何字符就能直接贴进对应输入框——绝不能把 `[unit_id] (Ns)` 也算进这段文本里。

审查完一条脚本后,每个 unit 按下面的结构输出,不要只给结论不给理由:

> **[unit_id] 判定:强 / 弱**
> 理由:(对应四问里哪一条不通过)
> 改写建议:(如果是弱单元,给出包含"主体+动作+运镜+景别"顺序的具体改写方向说明)
> 可粘贴文本:
> ```
> (改写后的完整正文字符串,即镜头描述+{台词},不含编号和时长前缀)
> ```

判定为"强"、不需要改写的 unit 可以不给"可粘贴文本"这一块。判定为"应合并到其他 unit"的,把"可粘贴文本"放在合并后的目标 unit 条目下,并在被合并 unit 自己的条目里注明"内容已并入 [目标 unit_id],此 unit 可删除",不要重复给两份。

全部 unit 过完后,总结:纯建立型 unit 占比是否超标、整条脚本的节奏是否符合"钩子→冲突→高潮→结局"的分布、时长和编号是否有缺口、情节时间线是否有颠倒、人物状态是否连贯、结构是否完整(是否埋了没接)、结尾引导是否统一、是否存在视觉重复度过高的 unit 组合、台词是否具备静音可读性、最值得优先改的 2~3 个 unit。

不要在改写建议里堆更多情节——每次改写只解决"这个 unit 有没有一个具体变化"的问题,不要顺手加第二次反转进去。
